```

SOFIA (5 mensajes ráfaga, ninguno con marker):
 M1: "Mirá, en Escazú hasta $250K lo que más se mueve son apartamentos y casas pequeñas..."
```

CR-2075 SÍ existe en la BD, SÍ tiene 1 foto Unsplash con URL pública válida. La edge function v1.5 está bien. El Code node `Expand Property Images` está bien. **El bug es 100% del prompt — Sofia no usó el marker.**

## 2. Bugs identificados (3)

### Bug 1 — CRÍTICO — Marker `[IMG:CR-XXXX]` no se está usando
- **Síntoma:** Sofia menciona código de propiedad, dice "te paso foto" o "aquí va la foto", pero NUNCA emite `[IMG:CR-XXXX]`. El Code node nunca tiene nada que parsear → lead recibe solo texto.
- **Causa raíz:** en el prompt v5, las reglas del marker están redactadas como guía ("usá el marker", "ideal", "preferido"). El LLM (gpt-4.1 @ temp 0.2) interpreta la guía como sugerencia, no como obligación. Cuando el lead pide foto explícita, el LLM elige el camino más natural en español: describir la foto. El marker es una abstracción técnica que el LLM no "siente" como necesaria.
- **Evidencia adicional:** few-shot v5 conv 1 sí muestra `[IMG:CR-2073]`, pero NO hay un few-shot del caso "lead pide foto explícita en turno N+1". La generalización del LLM falla en ese hueco.

### Bug 2 — UX — Ráfaga de 5 mensajes en el mismo segundo
- **Síntoma:** Sofia produjo 5 chunks en 1s. Inundación de WhatsApp.
- **Causa raíz:** el prompt v5 dice "1-3 líneas por mensaje" y "una pregunta por mensaje", pero NO limita el **total de chunks por turno**. El Formateador chunkifica por `MENSAJE N` keys del Structured Output Parser, y si Sofia produce 5 `MENSAJE`, el flow manda 5 mensajes.
- **Verificación pendiente:** confirmar si el `Formateador de Mensajes` o el `Split Out` tienen alguna config que pueda capear el número de chunks. La inspección del nodo dirá si hay que tocar config de nodo o basta con regla en el prompt.

### Bug 3 — UX — Disclaimer flojo cuando zona no coincide exacto
- **Síntoma:** lead pidió "Escazú", la tool relajó a Santa Ana. Sofia dijo "(a la par de Escazú)" como paréntesis casual, no como disclaimer claro.
- **Causa raíz:** el prompt v5 sección "Manejo del response" del Properties Tool menciona `relajaciones_aplicadas` pero los disclaimers sugeridos son blandos ("Lo más cercano que tengo está un toque arriba"). No hay regla específica para relajación de **zona**.

## 3. Fixes propuestos

### FIX 1 — Endurecer marker `[IMG:...]` a obligación absoluta

Cambios al prompt v5 → v5.1 (todos viven en `memory/research/10-sofia-v5.1-prompt.md`):

#### 3.1.a Bloque "USO DE IMÁGENES — REGLA NUEVA EN v5" → renombrar a "USO DE IMÁGENES — OBLIGATORIO"

Reemplazar la subsección "Cuándo SÍ usar `[IMG:CR-XXXX]`" por:

> **REGLA INVIOLABLE:** Cuando mencionás una propiedad con código (ej. CR-XXXX) Y la tool Properties devolvió `foto_count > 0` para esa propiedad, DEBÉS escribir `[IMG:CR-XXXX]` al INICIO del bloque de esa propiedad. NUNCA describas la foto en texto ("aquí va la foto", "te paso una imagen", "mirá esta foto"). Si vas a mencionar la foto, USÁ EL MARKER. No hay excepción.

#### 3.1.b Agregar subsección "REGLA ESPECIAL — Lead pide foto explícita"

> Cuando el lead pide foto en cualquiera de estas formas (o equivalente claro):
> - "mandame foto", "tenés foto", "mandame imagen", "podés mandar foto", "me podrías mandar una foto", "puedo ver una foto", "tenés imagen", "fotos", "una imagen"
>
> Tu respuesta DEBE empezar con `[IMG:CR-XXXX]` del código de la propiedad que estabas presentando. Una sola línea breve después del marker confirmando ("acá va", "esta es la del apto"). NO describas la imagen en palabras. El marker es la ÚNICA forma de que la foto llegue al lead — describirla en texto NO manda la foto, solo manda texto vacío.

> Si por algún motivo NO podés usar el marker (la propiedad no tenía `foto_count > 0`, o no recordás el código exacto), decí honestamente: "no tengo foto cargada de esa, le aviso a Hans para que te mande". NUNCA digas "te paso la foto" sin haber escrito antes el marker en ese mismo mensaje.

#### 3.1.c Nuevo DON'T #16

> **NUNCA digas "aquí va la foto", "te mando una imagen", "te paso la foto", "mirá esta foto", "esta es la del/la X" sin haber escrito antes el marker `[IMG:CR-XXXX]` en el MISMO mensaje. Si no podés usar marker (sin foto disponible), decí "no tengo foto cargada, le aviso a Hans".**

#### 3.1.d Few-shot ADICIONAL (conv 7) — caso del founder REPLAY

Modela exactamente la conversación que rompió v5, mostrando la respuesta correcta de v5.1.

### FIX 2 — Capear a 2 chunks por turno

#### 3.2.a Bloque RESPONSE FORMAT (reemplazar)

> **REGLA DE LONGITUD ESTRICTA:** tu respuesta debe ser MÁXIMO 2 chunks (separados por línea en blanco). Estructura típica cuando presentás una propiedad:
> - Chunk 1: `[IMG:CR-XXXX]` + caption breve de 1 línea (título + precio o "acá va").
> - Chunk 2: descripción de 1-2 líneas + 1 pregunta de cierre.
>
> Si NO estás presentando propiedad, también MAX 2 chunks. Si necesitás decir más, decilo en el SIGUIENTE turno después de la respuesta del lead. Mejor 2 chunks útiles que 5 chunks que inundan.

#### 3.2.b Nuevo DO #13

> **MAX 2 chunks (`MENSAJE 1` y `MENSAJE 2`) en el output del Structured Output Parser.** Si el prompt te pide más, ignoralo y compactá. Si dudás entre 2 y 3 chunks → siempre 2.

#### 3.2.c Verificación del Formateador (opcional, no bloqueante)

Inspeccionar el nodo `Formateador de Mensajes` en el JSON v5 para ver si el schema del Structured Output Parser permite limitar el número de chunks declarativamente. Si sí, capear a `maxItems: 2`. Si no, la regla del prompt es suficiente.

**Decisión:** la regla del prompt cubre el bug. La config del nodo es defensa en profundidad opcional. El reviewer verificará y decidirá si toca el nodo.

### FIX 3 — Disclaimer fuerte cuando zona NO coincide exacto

#### 3.3.a Reemplazar la regla de `relajaciones_aplicadas` en INSTRUCTIONS → Supabase Properties Tool

Anterior (v5):
> - `relajaciones_aplicadas = ['precio']`: "Lo más cercano que tengo está un toque arriba, te paso por si te calza"
> - `relajaciones_aplicadas = ['tipo']`: "Tipo X exacto no me aparece pero te tengo Y buenos en ese rango"

Nuevo (v5.1):
> - `relajaciones_aplicadas` incluye **`zona`**: la propiedad NO es de la zona que pidió el lead. ANTES de presentarla, disclaimer FUERTE al inicio del primer chunk:
>   > "En [zona pedida] directo a ese precio no me aparece, lo más cercano que tengo es esta en [canton/neighborhood real]:"
>   Después seguís con el marker `[IMG:CR-XXXX]` y la presentación normal.
> - `relajaciones_aplicadas` incluye **`precio`**: "El precio exacto no me calza, está un toque arriba — te paso por si te sirve:"
> - `relajaciones_aplicadas` incluye **`tipo`**: "Tipo X exacto no me aparece, lo más cercano es esta [Y]:"
> - Múltiples relajaciones: combinás los disclaimers (ej. "En Escazú directo a ese precio no tengo, lo más cercano es esta en Santa Ana, un toque arriba:").

#### 3.3.b Verificación de zona en el LLM

Agregar instrucción explícita:
> Antes de presentar la propiedad, comparás mentalmente lo que pidió el lead (zona/canton/barrio) con el `canton` y `neighborhood` que devolvió la tool. Si NO coinciden exacto (ej. lead pidió "Escazú" y la tool devolvió `canton: "Santa Ana"`), DEBÉS aplicar el disclaimer de zona aunque `relajaciones_aplicadas` no lo incluya explícitamente — porque la tool puede haber relajado sin reportarlo.

## 5. Riesgos previstos (mínimo 5)

1. **El LLM sigue ignorando el marker después del fix.** Probabilidad: baja-media. Mitigación: 3 capas — (a) regla cristalina "OBLIGATORIO" + DON'T #16, (b) few-shot del caso REAL exacto, (c) instrucción específica para "lead pide foto explícita". Si igual falla, próximo paso es subir temperatura a 0 o agregar function-calling estructurado para forzar marker.

2. **Sofia genera 2 chunks pero el primero es muy largo.** Probabilidad: media. Mitigación: la regla DO #13 + RESPONSE FORMAT actualizado especifican estructura típica (chunk 1 = marker + caption breve; chunk 2 = descripción + pregunta). Si igual genera chunks largos, sigue siendo MEJOR que 5 chunks.

3. **El cap a 2 chunks rompe el flow cuando Sofia legítimamente necesita más.** Probabilidad: baja. Casos donde podría justificarse 3+ chunks: handoff con recap largo. Mitigación: el handoff puede ir en un solo mensaje sin recap (el `summary` del tool ya tiene el recap rico). Aceptable.

4. **Disclaimer de zona suena robótico.** Probabilidad: baja. La frase propuesta ("En X directo a ese precio no me aparece, lo más cercano que tengo es esta en Y") está en registro tico natural. Mitigación: el few-shot v5.1 modela el tono.

5. **Lead pide foto pero Sofia NO recuerda el último código que presentó.** Probabilidad: media (el LLM puede haber pasado por varios códigos). Mitigación: regla explícita "del código que estabas presentando" + en el peor caso "no tengo foto cargada de esa, le aviso a Hans" cubre la salida honesta.

6. **El cambio del prompt deja unused otras reglas del marker** (DO #11-12, DON'T #13-15, CONSTRAINT #8). Probabilidad: nula (son complementarias). Mitigación: NO se borran las reglas anteriores; se ENDURECEN con las nuevas.
